## Seam

A new command lives in its own module, imports the root group with
`from .cli import cli`, decorates with `@cli.command()` or `@cli.group()`,
and is registered by adding one import line to **both**
`viur_cli.cli.main` and `viur_cli._docs_cli`. There is no discovery; a
module that is not imported there does not exist for the user and is
missing from the generated docs.

Removing a command: keep a hidden stub in `viur_cli.deprecated` that
prints the replacement, in the style of `deprecated.install` and
`deprecated.deploy`. `package.py` sets the removal version in
`_DEPRECATION_REMOVED_IN`; the shim goes away with that release.

## Rules

- Command modules read `config` only inside the command function. At
  import time `config` may be `None` (see `docs/adr/conf.md`).
- No star imports in `viur_cli/__init__.py`. The v2 pattern triggered the
  `project.json` load on `import viur_cli`; the package marker stays empty.
- `profile` is a positional `click.argument` with `default="default"`,
  placed after the action arguments. Every command follows this; do not
  turn it into an option in one place.
- Pass-through to external tools (`gcloud`, `app_server`) uses
  `context_settings={"ignore_unknown_options": True}` plus an
  `additional_args` argument with `nargs=-1`. Do not parse those flags.

## Traps

- `scriptor/cli.py` and `scriptor/login.py` import `scriptor_config`
  **from `..cli`**, not from `..conf`. That works only because `cli.py`
  does `from .conf import *`. Cleaning that star import up breaks the
  scriptor commands.
- The root `cli()` callback runs `uv self version` on every invocation
  with no error handling. Without `uv` on `PATH` even `viur --help`
  crashes with a traceback; a mismatch below `MINIMAL_UV` only warns.
- Shell completion is generated by re-running the `viur` console script
  with `_VIUR_COMPLETE` set. Renaming the script in `pyproject.toml`
  silently breaks `setup_autocomplete`.
- `deprecated.install` and `deprecated.deploy` are `hidden=True`, so they
  do not show up in `--help` or the docs but still swallow the old
  invocation with an error message instead of "no such command".

## Why not

- **Why explicit imports instead of entry points or `pkgutil` discovery**:
  eight modules, no third-party plugins, and the docs shim needs the same
  list. Two import lists are cheaper than a discovery mechanism nobody
  extends.
